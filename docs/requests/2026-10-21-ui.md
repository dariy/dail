# dail — Visual refresh after the mockups, and a theme library

Status: proposal (2026-10-21). The recommended choices are recorded in §8, and the items build on them. No item here
is scheduled yet; UI-1 comes first. When an item is picked, move it to `ROADMAP.md` and build it in the AGENTS.md §3
order. Most items change the GUI only (§3 steps 7 and 8). UI-11, UI-12, UI-14 and UI-16 add commands, settings or
data, so they take every step.

**Sources.** `docs/ui/` holds four screens exported from Stitch, plus the design notes
`monochrome_minimalist_mail/DESIGN.md`. Each screen is a `screen.png` and the `code.html` (Tailwind) it was rendered
from.

| Screen | Mode | What it shows |
|---|---|---|
| `inbox_triage_light_mode` | light | three panes; list rows with snippet and tags; reader with toolbar, 28 px subject, sender card, attachments, quick reply, triage footer |
| `conversation_thread_dark_mode` | dark | a conversation: collapsed messages, one expanded message, a code block, attachments, a reply composer docked below |
| `composer_command_bar_k` | dark | the command palette over a floating composer |
| `settings_shortcuts` | dark | a preferences page: tabs, a switch, segmented controls, key binding groups |

**The three asks.**
1. Restyle the project after the mockups.
2. Build a library of visual elements (colours, fonts, sizes and the other style elements) that themes are made of.
3. Ship a dark and a light theme now. Other colour schemes come later.

**In short.** M6 already gave the GUI DESIGN.md's monochrome palette (`app_gui::theme`), so colour is the smallest
gap. The larger gaps are these: egui's default font in one weight, emoji glyphs as icons, no top bar, a pure-black
dark mode, and about 140 literal sizes, radii, margins and spaces in 12 GUI modules. The plan adds a toolkit-free
crate, `app-theme`, with design tokens, built-in themes, bundled fonts and icons, and a contrast audit. It also adds
an egui adapter and a component kit in `app_gui::ui`. Then it restyles one surface at a time with them. A theme is
data: a new colour scheme is one table of values that passes the audit, and no widget changes.

## 1. Review of the mockups

### 1.1 Design language
- **Monochrome.** Depth comes from tonal planes and 1 px hairlines. There are no shadows and no colour accents.
- **Inversion for emphasis.** Primary buttons, the palette's cursor row and strong chips are white on black (dark)
  or black on white (light).
- **Weight and tone carry state.** Unread rows are semibold in the strongest text colour. Read rows are regular in a
  softer grey.
- **Monospace for metadata.** Times, counts, keys and section captions are in JetBrains Mono. Captions are in capitals
  with letter spacing.
- **Keys everywhere.** Every action shows its key in a small key cap. The pane footers list the keys.
- **Density.** Rows are 40 or 48 px. The reading column is at most 720 px wide.

### 1.2 Layout and sizes (from `code.html`; CSS px = egui points)
| Element | Size |
|---|---|
| Sidebar | 224 wide (`w-56`), full height. Brand row 56. Compose button full width. Nav rows 32 (icon 16, gap 8). Active row: selected fill and a 2 px bar. Settings is pinned at the bottom. |
| Top bar | 56 high, right of the sidebar: search pill (it opens the palette), sync state, key hint, avatar |
| List pane | 410 wide (light), 320 (dark); DESIGN.md says 360–440. Header 48, footer 40. Rows 40 (compact) or 48 (standard) in DESIGN.md; taller rows with snippet and tags in the screens |
| Reader | toolbar 48; padding 24; text at most 720 wide; subject 28/34; sender card; body 15/24 |
| Palette | 560 wide, 80 below the top bar; rows 36; section captions; footer 36 |
| Floating composer | 540 wide |
| Key cap | 18 high, padding 2 × 5, radius 2, mono 10–11 |
| Small controls | checkbox 14 (radius 2); switch 44 × 24 with a 20 px knob; avatars 28, 32 and 40; unread pip 6–8 |
| Icons | 16 in nav rows, 18 in icon buttons, 15 in text buttons, 20 in attachment tiles |

### 1.3 What to correct instead of copying
1. **Two colour sets.** The prose part of DESIGN.md ("Palette Architecture") gives zinc greys on pure black
   (`#000000`, `#09090B`, …). Its YAML front matter and the HTML use Material 3 neutrals instead: `#131315` surface,
   `#0e0e10` lowest, `#e5e1e4` on-surface, `#8e9192` outline. The screenshots are rendered from the HTML, so they
   show the Material 3 set. `app_gui::theme` implements the prose set today.
2. **The light screen is a hybrid.** The sidebar and the top bar stay dark (`bg-surface-container-lowest`). Only the
   content panes are white (`bg-tertiary`). The prose part of DESIGN.md asks for a light sidebar (`#FAFAFA`).
3. **Tinted greys.** The light screen's selected rows and cards have a faint blue cast (`#e2e1eb`, Material 3
   *secondary-fixed*). The dark set has faint tints too (`#131315`, `#e5e1e4`). DESIGN.md asks for an absolute
   monochrome.
4. **Serif labels are an export artefact.** In the PNGs, the small labels (tags, "4 Unread", "Sort: Priority", the
   sidebar's key letters) use a serif face. JetBrains Mono did not load in the renderer, and the CSS names no
   fallback, so the renderer used its default serif. The intended face is JetBrains Mono.
5. **Radii.** The Tailwind config in `code.html` (2 / 4 / 8 / 12 px) differs from DESIGN.md (2 / 4 / 6 / 8 / 12). The
   screens show 2–4 px on controls.
6. **macOS key glyphs** (⌘ ⌥ ⇧). dail runs on Linux and Windows, so it shows `Ctrl`, `Alt` and `Shift`. `↵` and the
   arrows stay.
7. **Names.** "NullMail" and "v2.4" become dail and `CARGO_PKG_VERSION`.
8. **Contrast.** Muted text (times, hints) fails WCAG AA (4.5:1 for small text) in most of the sets. The ratios
   below are computed:

   | Set | muted text on the page | on a selected row |
   |---|---|---|
   | `theme::DARK` today (`#71717A` on `#000000`) | 4.35 | 3.74 |
   | `theme::LIGHT` today (`#8A8A93` on `#FFFFFF`) | 3.42 | 3.11 |
   | DESIGN.md prose, light (`#A1A1AA`) | 2.56 | 2.33 |
   | mockup, dark (`#8e9192` on `#131315`) | 5.85 | 4.51 |
   | mockup, light (`#8e9192` on `#ffffff`) | 3.17 | 2.45 |

   A bug in the same area: an error toast draws `error_fg_color` on the ink fill. That is 1.70:1 in dark mode (pink
   on white) and 3.04:1 in light mode. UI-10 fixes it, and the audit (§3.7) would have caught it.

## 3. The theme library

### 3.1 Crate and dependencies
A new crate, `crates/app-theme`. It has no toolkit dependency.
- `app-theme ← (nothing internal)`. Its only external dependency is `serde`, so themes stay (de)serializable and
  theme files can come later.
- `app-gui ← app-core, app-sync, app-front, app-theme`. `app-tui` does not depend on it until UI-16.
- Why a crate, not an `app-front` module: tokens need nothing from `app-core`. A crate without internal
  dependencies can also feed a future web front-end (CSS custom properties; the roadmap's Web/PWA client). Fonts and
  icons are assets, and the front-end logic crate should not carry them.
- A new crate needs an ADR (AGENTS.md §7) and the topology updates in AGENTS.md §2 (a local, untracked file) and
  ARCHITECTURE §3.
- The crate's `license` names the font licences next to the code's, as `epaint_default_fonts` does:
  `(MIT OR Apache-2.0) AND OFL-1.1 AND Apache-2.0`. `deny.toml` already allows OFL-1.1.

### 3.2 Layers
```text
primitives        →   roles (per theme)                →   components (app_gui::ui)
grey ramp,            content and chrome surfaces,         button, key cap, badge, nav row, list row,
type scale,           their text, borders, inversion,      card, field, palette row, …
spacing, radii        danger, account tags                 read roles and metrics only
```
Widgets never see a hex value or a pixel number. They read a role or a metric. The egui adapter converts a theme to
egui types once per theme change.

```rust
pub struct Theme {
    pub id: Cow<'static, str>,     // "dail-dark": stable, stored in the settings (UI-11)
    pub name: Cow<'static, str>,   // "Dail Dark": shown in the settings page
    pub appearance: Appearance,    // Light | Dark: egui's dark_mode, scrollbars, text cursor
    pub content: Surface,          // list, reader, composer, dialogs
    pub chrome: Surface,           // sidebar and top bar; equal to `content` in a flat theme
    pub tags: [Rgba; 6],           // account colours
}

pub struct Surface {
    pub base: Rgba, pub canvas: Rgba, pub raised: Rgba, pub hover: Rgba,
    pub selected: Rgba, pub emphasis: Rgba, pub scrim: Rgba,
    pub border_subtle: Rgba, pub border: Rgba, pub border_strong: Rgba, pub focus: Rgba,
    pub text_strong: Rgba, pub text: Rgba, pub text_secondary: Rgba, pub text_muted: Rgba,
    pub inverse_bg: Rgba, pub inverse_text: Rgba,
    pub danger: Rgba, pub inverse_danger: Rgba,
}
```
All built-in themes share one `TypeScale` and one `Metrics` value (§3.4, §3.5). They are separate values, so a theme
can bring its own set later. Row density (compact or cozy) is a user setting (UI-11), not part of a theme.

### 3.3 Colour roles
The values are the screens' Material 3 tones, converted to neutral greys of the same luminance (§8: D1, D4).
Muted text is darker in light mode, so that it passes AA (D3).

|---|---|---|---|---|
| `base` | list pane, cards, chrome | `#0e0e0e` | `#ffffff` | M3 lowest `#0e0e10`; tertiary |
| `canvas` | reader, window background | `#131313` | `#ffffff` | M3 surface `#131315` |
| `raised` | pane headers, secondary buttons, inputs, attachment and settings cards | `#1b1b1b` | `#f2f2f2` | M3 container-low `#1c1b1d` |

| `selected` | selected row, active nav row, key caps | `#2a2a2a` | `#e2e2e2` | M3 container-high `#2a2a2c`; secondary-fixed `#e2e1eb` |
| `emphasis` | badges, icon tiles, search marks | `#343434` | `#e2e2e2` | M3 container-highest `#353437` |
| `border_subtle` | hairline dividers | `#222222` | `#e9e9e9` | outline-variant at 30 %; ink at 10 % |
| `border` | inputs, overlays, chips | `#2f2f2f` | `#d7d7d7` | outline-variant at 55 %; ink at 18 % |
| `border_strong` | checkbox and switch outlines (at least 3:1) | `#6b6b6b` | `#8a8a8a` | darker than the screens, for 3:1 |
| `focus` | focus ring, keyboard cursor bar | `#ffffff` | `#0e0e0e` | DESIGN.md: focus raises the border to the ink colour |

| `danger` | failures in the status, the composer and the wizard | `#ffb4ab` | `#b3261e` | `theme.rs` uses these today |
| `inverse_danger` | failures on an inverse fill (toasts) | `#b3261e` | `#ffb4ab` | new (fixes the 1.70:1 toast) |
| `scrim` | behind dialogs and the palette | `#000000` at 60 % | `#0e0e0e` at 40 % | the screens dim the page to 35 % and blur it |

- **Chrome.** In `dail-light`, the chrome group is `dail-dark`'s content group: dark sidebar and top bar, as in the
  light screen (D2). A flat light theme sets chrome to its content group.
- **High contrast.** Today's `theme` 3 and 4 palettes become `dail-dark-hc` and `dail-light-hc`, with the same values
  in the new roles. Exception: the audit finds `danger` on `hover` in `dail-light-hc` at 4.497:1, just below AA. A
  darker red (`#9c1f17`, 5.5:1) fixes it.
- **Account tags.** The six hues of `theme::ACCOUNT_COLORS` stay as `Theme.tags`. They carry information, not
  accent. A strict theme can replace them with greys.
- **Audit result.** With these values, all four built-in themes pass §3.7. The lowest ratios are `text_muted` on
  `selected`: 4.79 (dark) and 4.71 (light).

**Fonts** (bundled in `app-theme/assets/fonts/`, each with its licence text, its source version and, for the subset,
the command that made it, as `epaint_default_fonts/fonts/egui-icons.txt` does):

| File | Licence | Use |
|---|---|---|
| `Geist[wght].ttf`, variable | OFL-1.1 (Vercel) | sans, weights 400, 500, 600 |
| `JetBrainsMono[wght].ttf`, variable | OFL-1.1 (JetBrains) | mono, weights 400, 500, 600 |

**In egui 0.37.**
- **Weights.** Each variable font is registered once per weight, with `FontTweak::coords` (`wght` 400, 500, 600).
  The families are `sans`, `sans-500`, `sans-600`, `mono`, `mono-500` and `mono-600`. The `Blob` is shared, not
  copied. `RichText::variation("wght", …)` covers one-off weights.
- **Fallbacks.** egui's built-in fonts stay as fallbacks, so scripts that Geist lacks still render as they do today:
  `sans` → Geist, Ubuntu-Light, egui-icons, NotoEmoji, emoji-icon-font. `mono` → JetBrains Mono, Hack, Ubuntu-Light,
  then the same emoji fonts.
- **Tracking and line height.** The kit's text helper sets them through `TextFormat::extra_letter_spacing` (em ×
  size) and `TextFormat::line_height`. `TextEdit` takes only a `FontId`, so input fields get no tracking. Only titles
  and captions use tracking, so no input is affected.
- **egui's own widgets.** The `TextStyle`s map onto the tokens: Body → `body_md`, Small → `body_sm`, Button →
  `body_md` at 500, Heading → `headline_lg`, Monospace → `label_md`. egui's built-in widgets then match the kit.

### 3.6 Icons
- **Font.** A subset of Material Symbols Outlined (Apache-2.0, the screens' icon set) with about 50 icons. It keeps
  the `FILL` and `wght` axes, so a starred star and the active nav icon can be filled. `opsz` is fixed at 20 and
  `GRAD` at 0. fontTools makes the subset (`varLib.instancer`, then `subset --unicodes=…`). The command and the icon
  list are in the font's README. The result is a few tens of KB, against megabytes for the full variable font.
- **Names.** `app_theme::Icon` is an enum of names with their code points (from the upstream `.codepoints` file):
  `Mail` (brand), `Edit` (compose), `Inbox`, `AllInbox`, `Send`, `Draft`, `Archive`, `Delete`, `Report` (junk),
  `Star`, `Folder`, `Settings`, `Search`, `DockToLeft`, `Sync`, `Reply`, `ReplyAll`, `Forward`, `MarkEmailRead`,
  `MarkEmailUnread`, `DriveFileMove`, `Close`, `ExpandLess`, `ExpandMore`, `UnfoldMore`, `UnfoldLess`, `MoreHoriz`,
  `AttachFile`, `Download`, `OpenInNew`, `Description`, `Image`, `PictureAsPdf`, `CheckBox`,
  `CheckBoxOutlineBlank`, `Warning`, `Error`, `Schedule`, `Undo`, `Keyboard`, `Contrast`, `Person`, `Add`,
  `Visibility`, `VisibilityOff`, `Link`, `ContentCopy`, `VerifiedUser`, `CloudOff`, `LightMode`, `DarkMode`,
  `ChevronRight`.
- **Accessibility.** Icons are painted with `Painter::text`, not added as labels, so screen readers never read
  private-use characters. The widget around an icon carries the name, as `widgets::icon_button` does today.
- **Side effect.** The GUI gets a real check mark. ARCHITECTURE §7.1 says the GUI fonts have no `✓`.

### 3.7 Contrast audit
`app_theme::audit(&Theme) -> Vec<Problem>` checks the role pairs that the components use (WCAG 2.x relative
luminance). It does not check every combination.
- `text_strong`, `text` and `text_secondary` on `base`, `canvas`, `raised`, `hover`, `selected` and `emphasis`:
  at least 4.5:1.
- `text_muted` and `danger` on `base`, `canvas`, `raised`, `hover` and `selected`: at least 4.5:1. They are never
  drawn on `emphasis`.
- `inverse_text` and `inverse_danger` on `inverse_bg`: at least 4.5:1.
- `focus` on `base`, `raised` and `selected`, and `border_strong` on `base` and `raised`: at least 3:1 (WCAG 1.4.11,
  non-text contrast).
- Hairlines (`border_subtle`, `border`) are decorative and exempt. A control is never told apart by its hairline
  alone: an input has its `raised` fill, and on focus the focus ring.
- Each pair is checked in both surface groups (content and chrome).

The rules are a unit test over every built-in theme. They are also the gate for theme files later.

### 3.8 Components (`app_gui::ui`)
The kit replaces `widgets.rs` and the ad-hoc frames. Each component reads roles and metrics only, keeps today's
accessible names, and draws the focus ring for keyboard focus.

| Component | Look | Replaces |
|---|---|---|
| `text(token, role)` | a type token in a colour role: weight family, tracking, line height, capitals for captions | `RichText::new(…).size(…)`, `widgets::mono` |
| `icon(Icon, size, role)` | a painted glyph, 14 / 16 / 18 / 20; `filled` for the starred and active states | emoji glyphs |

### 3.9 Adding a colour scheme later
1. Add a `Theme` value to `app-theme` with both surface groups and the account tags. Later this can be a theme file.
2. Run `cargo test -p app-theme`. The audit must pass.
3. The theme then appears in the settings page and in the palette's `set_theme` picker. Both list
   `app_theme::builtin::all()`.
4. Look at it in the gallery: `--theme <id>`.

No widget, command or setting changes. **Theme files** (not in this plan): `<config dir>/themes/<id>.toml` with the
same fields, colours as `"#rrggbb"` strings. The GUI reads them at start and audits them. A theme that fails the
audit is listed with its problems and is not applied. The rest are offered next to the built-ins.

### UI-11 — Themes by name, and the row density
- **Settings.** `theme` (u64) stays and means the mode: 0 follows the system, 1 is light, 2 is dark. Two new string
  settings, `theme_light` (default `dail-light`) and `theme_dark` (default `dail-dark`), name the theme for each
  mode.
- **Legacy values.** `theme = 3` becomes `theme = 2` with `theme_dark = "dail-dark-hc"`. `theme = 4` becomes
  `theme = 1` with `theme_light = "dail-light-hc"`. This happens when `config.toml` is read (app-io) and when
  `set_setting {key: "theme", value: 3 or 4}` runs (engine), so old configs, scripts and agents keep working. The ADR
  records this change of meaning (AGENTS.md §5: serialization stability).
- **Command** `set_theme { mode?: system | light | dark, light?: string, dark?: string }`.
  - Kind: Mutation (undoable, one step for the whole change). Agents: allowed (only the look changes, and no data
    leaves). Category: App. No default keys.
  - Errors: `invalid_argument` when no field is given, or when a name is not a slug (`[a-z0-9-]{1,64}`).
  - The core does not know the list of themes (`app-core` cannot depend on `app-theme`). For an unknown name, the GUI
    uses the default theme of that mode and shows a notice.
  - The doc comment lists the built-in names. A GUI test keeps that list equal to `app_theme::builtin::all()`.
- **Setting** `list_density` (a `SettingKey`): 0 = cozy (two lines, 48 px), 1 = compact (one line, 40 px). It
  replaces UX-13's numbers (D10).
- **Palette flow** (`app_front::palette::flow`): `set_theme` asks for the mode, then optionally the theme for that
  mode.
- **Tests:**
  - app-core: happy path, every error, undo → redo, the replay fixture `tests/replay/set_theme.jsonl`, and the
    registry pin (`tests/it/registry.rs`);
  - app-io: `theme = 3` in a config maps to the names;

### UI-16 — TUI colours from `app-theme` (optional)

- An opt-in setting, `tui_colors` (0 = terminal colours, the default; 1 = truecolor), maps the active theme's roles
  onto ratatui colours: fills onto backgrounds, text roles onto foregrounds, `selected` onto the selection, inversion
  onto reverse. `NO_COLOR` still wins.
- It needs an amendment to ADR 0004. This is the TUI side of "more schemes later".

## 6. Risks
- **Small sizes.** Geist at 12–13 px on a 96-dpi screen may look soft with egui's rasterizer. Check the hinting
  (`FontTweak::hinting`) in the gallery on both platforms. Fall back to 13 and 14 px base sizes if needed.
- **No blur in egui.** Overlays use an opaque fill and a scrim instead of `backdrop-filter`.
- **Dark chrome in a light theme.** egui has one `dark_mode` per style. The sidebar and the top bar set their own
  `Visuals` (UI-4), so their scrollbars, inputs and tooltips match.
- **Test churn.** Part B moves widgets. Keep the AccessKit names, and move each assertion with its widget (for
  example, the `statusbar.rs` tests go to the top bar and the list footer).
- **egui upgrades.** Only the adapter touches `Visuals` and `Style`. Widgets go through the kit.
- **Font licences.** OFL needs its licence text next to the font in every package (UI-2).

## 8. Recommendations (recorded 2026-10-21)
The items above build on these choices. Each one names the alternative it was weighed against and why that lost.
To reverse a choice, change it here first, then the items that cite it.

1. **D1 — Dark colours:** the screens' Material 3 tones as neutral greys (§3.3). Not DESIGN.md's prose values on
   pure black (today's): the screens are the approved look, and their muted text passes AA (5.85:1) where today's
   does not (4.35:1).
2. **D2 — Chrome in light mode:** a dark sidebar and top bar, as in the light screen. Not a fully light window, as
   DESIGN.md's prose says: all four screens share the same dark chrome. The chrome group stays separate in the token
   model, so a flat light theme is still one table away.
3. **D3 — Muted text:** darker in light mode, `#626262` (4.71:1 on a selected row). Not the screens' `#8e9192`, which
   is 3.17:1 on white and fails AA.
4. **D4 — Greys:** neutral (equal red, green and blue) at the luminance of the screens' tones. Not the screens'
   faint tints (`#e2e1eb`, `#131315`): DESIGN.md asks for an absolute monochrome, and neutral roles are easier to
   derive new schemes from.
5. **D5 — Fonts:** bundle Geist, JetBrains Mono and the Material Symbols subset. Not the system's fonts: the look
   would differ on each machine, and the screens depend on these faces. The cost is a few hundred KB; egui's own
   default fonts take about 1.4 MB.
6. **D6 — Library location:** a new crate, `app-theme`, with an ADR. Not an `app-front` module: tokens need nothing
   from `app-core`, a crate without internal dependencies can feed a future web front-end, and fonts are assets.
7. **D7 — Status bar:** it goes away. The sync state and the status chip move to the top bar, and the undo label to
   the list footer. Not a restyled bottom status bar: the screens have none, and every item keeps a visible place.
8. **D8 — Search:** the top bar's pill opens the palette, and `/` opens the palette at its search step. Not an inline
   search field: the palette already offers "Search mail for …", and one entry point is simpler.
9. **D9 — Themes by name:** now, with the settings page (UI-11). Not `theme` 0–4 until a third scheme exists: the
   high-contrast palettes already are the third and fourth schemes, and the settings page needs a clean model. Old
   values keep working (UI-11).
10. **D10 — Row heights:** 48 (cozy, two lines) and 40 (compact, one line), from the screens and DESIGN.md. Not
    UX-13's 52 and 28.
